## 4. Refund showing NEFT when refunded in cash — FIXED

The refund row had no payout-mode column, so a refund always reported the *original
receipt's* method.

- Added `payment_method` + `refund_ref` to `refunds` (migration
  `20260722000000_add_refund_mode`, written with `IF NOT EXISTS` because some
  environments already had `payment_method` from an out-of-band migration).
- Refund modal now has a **Refunded via** selector (Cash / UPI / Card / Bank Transfer /
  NEFT/RTGS / Cheque), a reference field for non-cash payouts, and an inline warning when
  the payout mode differs from how it was collected.
- Refund History now shows **Original Receipt · Collected Via · Refunded Via**, with a
  mismatch highlighted in amber. Legacy rows fall back to the original payment's method.
- The payment receipt's refund block prints "refunded via <mode>".

- [prisma/schema.prisma](prisma/schema.prisma), [app/components/finance/RefundModal.tsx](app/components/finance/RefundModal.tsx), [app/actions/finance-actions.ts](app/actions/finance-actions.ts), [app/finance/refunds/page.tsx](app/finance/refunds/page.tsx), [app/api/payment/[id]/receipt/route.ts](app/api/payment/%5Bid%5D/receipt/route.ts)

**Verified:** processed a ₹1 refund on a Cash receipt with payout NEFT/RTGS. History now
reads `AXT-RCP-26-27-186 · ₹1.00 · Collected via Cash · Refunded via NEFT/RTGS`.

## Notes for the team

- **Migration to deploy:** `20260722000000_add_refund_mode` (adds
  `refunds.payment_method`, `refunds.refund_ref`, and `patient_deposits.cancelled_reason /
  cancelled_by / cancelled_at`). All columns nullable and additive, written with
  `IF NOT EXISTS` — safe to re-run.
- **Migration drift:** the demo DB already had three migrations that are not in this
  repo (`20260720000000_add_voice_call_assistant_fields`,
  `20260721000000_add_refund_payment_method`, `20260721010000_add_tpa_package_naming`).
  Pre-existing, not introduced here, but the branches should be reconciled before the
  next production deploy.
- **Test data on the demo DB:** the test asset, the cancelled test deposit and the
  verification patient note were all deleted after testing; the stock adjustment and the
  invoice doctor change were reverted to their original values. **One record was left in
  place deliberately:** the ₹1 refund on receipt `AXT-RCP-26-27-186` (reason "Automated
  verification of refund payout mode"). Removing it would mean hand-editing the invoice's
  `paid_amount` / `balance_due`, which is riskier than leaving a labelled ₹1 row — and it
  is the live evidence that the Cash→NEFT payout fix works. Delete it properly through the
  app if you want the demo pristine.
- **Separate cosmetic bug spotted:** IPD bill medicine lines render the doctor as
  "Dr. Dr.Shiv Chopra" — a double honorific from name formatting. Not in this scope.
- `npm run dev` fails locally: `prisma generate` hits an EPERM lock on
  `query_engine-windows.dll.node` whenever a dev server is already running. Use
  `npx next dev` to skip the `predev` step, or stop the server before generating.
